What do we actually do in LLD?

I think of LLD as answering a few simple questions.

1. What are the objects?

For a parking lot:

Vehicle
ParkingSpot
ParkingFloor
ParkingLot
Ticket
Payment
2. What does each object do?

For example:

ParkingLot
→ manages parking floors/spots

ParkingSpot
→ knows whether it is occupied

Ticket
→ keeps track of parking information

The important thing is that one class shouldn't start doing everything.

3. How are the objects connected?

For example:

ParkingLot
    |
    └── ParkingFloor
            |
            └── ParkingSpot
                    |
                    └── Vehicle

Now I need to decide what kind of relationship makes sense.

This is where concepts like:

Association
Aggregation
Composition
Inheritance

start becoming useful.

4. How will the system behave?

Suppose a car enters.

Maybe the flow is:

Car arrives
    ↓
EntryGate
    ↓
Find available spot
    ↓
Assign spot
    ↓
Generate Ticket

LLD isn't only about drawing classes.

We also care about how these objects interact.

LLD is not "write every detail"

This was something I had to clear up for myself.

LLD does not mean:

"Let's decide every single line of code before opening VS Code."

😂

The purpose is to decide the important structure and responsibilities before implementation.

We want enough clarity that when we start coding, we're not randomly creating classes and putting methods wherever they seem to fit.
