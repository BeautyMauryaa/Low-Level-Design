

# OOP — Object-Oriented Programming

Before going deeper into LLD, I need to be comfortable with OOP.

Because when we're doing LLD, we're basically trying to model a real problem using **objects, their responsibilities, and the way they interact**.

So instead of thinking only:

```text
What functions do I need?
```

I also start thinking:

```text
What objects exist?
What does each object know?
What can each object do?
Who should be responsible for what?
```

That's the connection between **OOP and LLD**.

---

# What is OOP?

**OOP = Object-Oriented Programming**

The basic idea is to organize code around **objects** instead of keeping everything as separate functions and data.

For example, if I'm building a parking system, I can identify things like:

```text
Vehicle
ParkingSpot
ParkingLot
Ticket
Payment
```

Each object has its own data and behavior.

For example:

```text
Vehicle
----------------
Data:
- vehicleNumber
- vehicleType

Behavior:
- getVehicleNumber()
- getVehicleType()
```

So an object can basically be thought of as:

> **Data + Behavior**
