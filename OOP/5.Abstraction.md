
# 2. Abstraction 🎭

Abstraction means:

> **Expose what is necessary and hide unnecessary implementation details.**

For example, when I use:

```text
payment.pay(500);
```

I don't need to know everything happening internally:

```text
Validate payment
      ↓
Authenticate
      ↓
Talk to bank
      ↓
Process transaction
      ↓
Update transaction
      ↓
Return result
```

I just need a simple interface like:

```text
pay(amount)
```

In code:
Payment
----------------
+ pay(amount)

The caller doesn't need to know exactly how payment happens.

The complicated implementation can stay hidden.

### Why useful in LLD?

It lets us work with **what something does** without depending on **how it does it**.

This becomes especially important when we start using:

* Interfaces
* Abstract classes
* Polymorphism
* Design patterns

### Simple way I remember it:

> **"I care about what it does, not all the stuff happening inside."**

---

```text
#include <iostream>

// Abstract Interface (The Contract)
class Printer {
public:
    virtual void print() = 0; // Pure virtual function
};

// Concrete Implementation 1
class LaserPrinter : public Printer {
public:
    void print() override { std::cout << "Printing using laser and toner...\n"; }
};

// Concrete Implementation 2
class InkjetPrinter : public Printer {
public:
    void print() override { std::cout << "Printing using liquid ink sprays...\n"; }
};

int main() {
    // The user interacts only with the abstract "Printer" concept
    Printer* myPrinter = new LaserPrinter();
    
    myPrinter->print(); // Output: Printing using laser and toner...

    delete myPrinter;
    return 0;
}

```
