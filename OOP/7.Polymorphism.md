

# 4. Polymorphism 🎨

This one sounds complicated at first, but the basic idea is:

> **Same interface, different behavior.**

Suppose I have:

```text
Payment
   |
   ├── UPI
   ├── Card
   └── PayPal
```

All of them can have:

```text
pay()
```

But the implementation can be different.

```text
UPI
→ UPI payment logic

Card
→ Card payment logic

PayPal
→ PayPal payment logic
```

The code using the payment doesn't need to care about the exact implementation.

It can simply do:

```text
payment.pay();
```

and the appropriate implementation handles it.

---

# Why Polymorphism matters in LLD

This becomes useful when the system needs to support different variations of the same thing.

For example, today:

```text
Payment
 ├── UPI
 └── Card
```

Tomorrow:

```text
Payment
 ├── UPI
 ├── Card
 ├── PayPal
 └── Wallet
```

If the design is good, adding `WalletPayment` shouldn't mean modifying a huge `if-else` block everywhere.

Instead, I can add another implementation.

This is one reason **interfaces + polymorphism** are so common in LLD.

---

```text

if(paymentType == "UPI") {
   ...
}
else if(paymentType == "CARD") {
   ...
}
else if(paymentType == "PAYPAL") {
   ...
}

Better:
Payment
   ↑
 ┌─┴───────────────┐
UPI              Card
pay()            pay()
