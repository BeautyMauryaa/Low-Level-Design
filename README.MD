# Low-Level Design (LLD)

I started learning LLD because I wanted to understand what actually happens before we start writing code.

At first, I thought software design was mostly about creating diagrams and then implementing them. But LLD is more about deciding how the code itself should be structured so that a system doesn't become difficult to understand, maintain, or extend as it grows.

## What is LLD?

LLD stands for **Low-Level Design**.

In simple words, LLD is the detailed design of a system at the code and object level.

Before implementing a feature, we think about:

- What classes do we need?
- What objects will exist?
- What responsibility should each class have?
- How should different classes interact?
- What methods and attributes should they contain?
- When should we use interfaces?
- Where should inheritance or composition be used?
- How can we make the design easier to maintain and extend?

The idea is to move from:

**"What should the system do?"**

↓

**"How should I structure the code to make it happen?"**
