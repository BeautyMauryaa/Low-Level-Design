# 🧠 System Design

A practical learning repository where I’m learning and documenting **System Design**, with a primary focus on **Low-Level Design (LLD)** and the fundamentals of **High-Level Design (HLD)**.

The goal is not just to memorize concepts, but to understand **how real software systems are designed, why certain design decisions are made, and how those decisions translate into clean, maintainable code.**

---

## 📌 What I'm Learning

### 🔹 Low-Level Design (LLD)

LLD focuses on designing software at the **object and code level**.

Topics include:

* OOP & Object Modeling
* Classes & Objects
* Encapsulation
* Abstraction
* Inheritance
* Polymorphism
* Composition
* Association, Aggregation & Composition
* SOLID Principles
* Interfaces
* UML & Class Diagrams
* Design Patterns
* Clean & Maintainable Code
* Extensibility & Reusability
* LLD Case Studies

### 🔹 High-Level Design (HLD)

HLD focuses on the **overall architecture and structure of a system**.

Topics include:

* System Architecture
* Client-Server Architecture
* Monolithic vs Microservices
* Scalability
* Availability & Reliability
* Load Balancing
* Caching
* Database Design
* Replication & Sharding
* Message Queues
* REST APIs
* WebSockets
* CDN
* Distributed Systems Basics
* CAP Theorem
* HLD Case Studies

## 🧩 How I'm Approaching System Design

For every concept or problem, I try to understand:

```text
Understand the Requirement
          ↓
Identify the Components
          ↓
Define Responsibilities
          ↓
Define Relationships
          ↓
Choose the Right Design
          ↓
Think About Trade-offs
          ↓
Implement / Document
```

For LLD problems, the focus is mainly on:

> **Objects → Responsibilities → Relationships → Behavior → Extensibility**

For HLD problems:

> **Requirements → Architecture → Components → Data Flow → Scalability → Trade-offs**

## 🎯 Goal

The goal of this repository is to build a strong understanding of **software design and system thinking** through continuous practice.

I want to be able to look at a problem and think beyond:

> **"How do I code this?"**

and start thinking:

> **"How should I design this so that it remains clean, flexible, scalable, and easy to change?"**
